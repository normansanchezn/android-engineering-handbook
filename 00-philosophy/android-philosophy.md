# Android Philosophy

## Goal

Build software that is easy to understand, test, extend, and maintain.

## Principles
- Read before writing.
- Understand before changing.
- Reuse before creating.
- Extend before replacing.
- Prefer clarity over cleverness.
- Keep modules independent.
- Keep business logic out of the UI.
- Prefer immutable state.
- Make dependencies explicit.
- Design for testing.

## Success Criteria

Good code is:
- Predictable
- Consistent
- Testable
- Modular
- Readable

Everything else in this playbook expands these principles.
